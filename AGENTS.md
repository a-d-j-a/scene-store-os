# Rules binding this agent to the user

## Hard rules (violations not tolerated)

- **Take the given time.** When the user gives time for a task, do not respond early. Completing early is a failure, not a win.
- **Never settle.** If you think you found something, try harder. First "found it" is not a finding; the deepest pit is one layer below. Verify from primary sources, not summaries.
- **No asking what was already answered.** Do not stop for clarification when the path is clear; continue with next steps instead.
- **No compromises on the project.** Full-fledged desktop. Nothing is stripped or scoped away to make it easier.
- **Create our own unless absolutely necessary.** Build every layer ourselves instead of reusing existing ones. Adopt someone else's code only when there is no way to build it ourselves (e.g. kernel boundaries, hardware drivers) â€” and justify it in writing each time.
- **Apps policy: reuse-first.** For end-user applications, prefer existing real software over custom code: ship apk/busybox/CLI tools (they run in the real PTY terminal), adopt real codecs/engines at the OS seam (honest boundary), run vi/nano instead of a custom editor. Write custom app code ONLY where no existing software can speak the scene protocol (thin protocol consumers â€” files browser, media viewers, search overlay) or where the app exists to prove/improve the OS layer itself. Never write an app just because integration is harder. Justify each first-party app in one line.
- **Never hallucinate.** No invented facts, fabricated sources, fake findings, or empty promises. Everything claimed must be verified or explicitly marked as unverified; never state something as done when it isn't.
- **Use parallel sub-agents.** Delegate independent work to as many sub-agents as possible, in parallel, to boost efficiency. Do not duplicate their work while they run. When a task has multiple phases or a lot of work, split it across multiple sub-agents (one per phase or per independent unit) instead of doing it all sequentially myself.
- **Use maximum amount of focus.** Apply the highest level of attention and rigor on the task at hand; no half-effort, no distractions, no drifting.

## Project: semantic scene engine (OS layer, not re-skin)

### Product goal (what we are building, never lose sight of it)
- An OS that is as fast and light as antiX/Puppy â€” boots and runs on hardware those run on â€” but does not look like 1999, and is deeply customizable.
- Modern appearance and deep customization must come from the OS layer itself (the semantic scene), not from piling on heavyweight shells/effects that cost the speed.
- Re-theme of running apps, OS-wide live theming, cross-app search/automation, replay â€” these are the customizability; a few MBs of memory and instant response are the speed. Both come from the same layer: the scene store.
- Any feature decision is tested against this goal: does it keep speed at antiX/Puppy level and does it make the look modern and the UI customizable?

- The OS owns the **meaning** of every native app's visible UI: regions, roles, labels, values, text, geometry, focus â€” per frame, versioned. Drawing is downstream of that.
- Novel asset is **understanding**, not rendering. Plan 9 devdraw, NeWS, BeOS = rasterizer channels. Fuchsia Flatland = retained composition, no semantics. On Linux the only semantic sources are accessibility trees (AT-SPI, GNOME's in-progress Newton prototype) â€” mirrors exported from apps for a11y consumers, not stored, versioned, or owned by the OS; no replay, no re-theme, no automation service. Windows UIA and macOS AX are read-mostly trees, same class. The OS-owned semantic scene remains open ground on Linux.
- Capabilities that fall out of the semantic scene: cross-app live search, cross-app UI automation as an OS service, deterministic whole-desktop replay/testing, re-theme of running apps, ghost-crash recovery, zero-cost capture.
- Honest boundary (stated, never hidden): browser/video/WebGL arrive as composited textures â€” effects applied, not semantically owned. Semantic scene is for native apps.
- Construction order: **scene store first** (versioned display lists + region semantics + op log). Compositor, effects, search, automation, a11y, rewind are consumers of it.
- Wire format is locked before any code.
